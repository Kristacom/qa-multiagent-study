REQ-AUTH-001 — Отображение кнопки «Войти» для неавторизованного пользователя
Приоритет:
P0
Тип:
UI
Компонент:
Auth
Описание:
На главной странице неавторизованному пользователю должна быть видна кнопка «Войти», обеспечивающая переход к форме авторизации.
Предусловие:
Пользователь не авторизован.
Критерии приёмки:
При открытии главной страницы кнопка «Войти» отображается.
При нажатии на кнопку происходит переход на
/login
.
Ожидаемый результат:
Кнопка видна, клик ведёт на страницу авторизации.
REQ-REG-002 — Валидация поля «Email» при регистрации
Приоритет:
P1
Тип:
UI + Validation
Компонент:
Registration
Описание:
Поле Email при регистрации проверяется на корректность формата перед отправкой формы.
Предусловие:
Открыта форма регистрации.
Критерии приёмки:
Email без
@
→ ошибка «Некорректный email».
Email с пробелами → ошибка «Некорректный email».
Корректный email (
user@example.com
) → ошибки нет, кнопка «Зарегистрироваться» активна.
Ожидаемый результат:
Валидация срабатывает на невалидных значениях и не срабатывает на валидном.
REQ-CHECKOUT-003 — Оформление заказа с выбором способа доставки
Приоритет:
P0
Тип:
Business logic + UI
Компонент:
Checkout
Описание:
На шаге оформления заказа пользователь выбирает способ доставки: «Курьер» или «Самовывоз». Состав полей формы зависит от выбранного способа.
Предусловие:
В корзине есть хотя бы один товар; пользователь авторизован.
Критерии приёмки:
«Курьер» → отображаются поля «Адрес» и «Дата доставки».
«Самовывоз» → отображается поле «Пункт выдачи» (dropdown), поля «Адрес» и «Дата доставки» скрыты.
Переключение между способами доставки очищает ранее введённые данные.
Кнопка «Оформить заказ» активна только при заполнении всех обязательных полей для выбранного способа.
Ожидаемый результат:
Форма динамически меняется, валидация учитывает выбранный способ.
